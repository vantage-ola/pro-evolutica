# Android verification

## Toolchain

The checked Mac has SDK platform 35, Build Tools 34.0.0, NDK 28.2.13676358
(r28c), JDK 21.0.11, cached Gradle 8.9 and Android Gradle Plugin 8.7.2.
CMake and SDL3 were not found in the checked locations. The build targets API 23
or newer and only `arm64-v8a`.

## Renderer compile

Using `NDK` for the installed NDK directory:

```bash
mkdir -p private/native-checks
"$NDK/toolchains/llvm/prebuilt/darwin-x86_64/bin/clang++" \
  --target=aarch64-linux-android23 -std=c++17 \
  -Wall -Wextra -Wpedantic -Werror -fPIC \
  -c native/rendering/triangle.cpp -o private/native-checks/triangle.o
"$NDK/toolchains/llvm/prebuilt/darwin-x86_64/bin/llvm-readelf" \
  -h private/native-checks/triangle.o
```

Both commands returned 0. Compilation emitted no diagnostics; the object header
reports `ELF64`, little endian, `REL`, `AArch64`. This checks the renderer's C++
against the real Android headers. It does not link SDL, compile the GPU shaders
or establish a working APK.

## Build configuration

Gradle 8.9 configured the Android project successfully with JDK 21 and the
installed SDK, using a project-local copy of cached dependencies and
`--offline --no-daemon help`. The same check through the generated wrapper also
passed, using the already cached Gradle distribution:

```bash
export GRADLE_USER_HOME="$PWD/private/gradle"
./android/gradlew -p android --offline --no-daemon help
```

`JAVA_HOME` and `ANDROID_HOME` pointed to the installed JDK 21 and SDK. Result:

```text
BUILD SUCCESSFUL in 5s
1 actionable task: 1 executed
```

The wrapper was generated by the cached Gradle installation without downloads.
Its JAR SHA-256 is
`498495120a03b9a6ab5d155f5de3c8f0d986a449153702fb80fc80e134484f17`,
which matches Gradle's [official checksum](https://gradle.org/release-checksums/#v8.9).
The distribution ZIP checksum is pinned in the wrapper properties. Configuration
does not run the CMake compiler, resolve the missing SDL AAR or build an APK.
