# Android verification

## Toolchain

The checked Mac has SDK platform 35, Build Tools 34.0.0, NDK 28.2.13676358
(r28c), JDK 21.0.11, cached Gradle 8.9 and Android Gradle Plugin 8.7.2.
CMake 3.22.1 and the SDL3 3.4.18 AAR are now present. The build targets API 23
or newer and only `arm64-v8a`.

## Renderer compile

Using `NDK` for the installed NDK directory:

```bash
mkdir -p private/native-checks
"$NDK/toolchains/llvm/prebuilt/darwin-x86_64/bin/clang++" \
  --target=aarch64-linux-android23 -std=c++17 \
  -Wall -Wextra -Wpedantic -Werror -fPIC \
  -c native/rendering/triangle.cpp -o private/native-checks/triangle.o
"$NDK/toolchains/llvm/prebuilt/darwin-x86_64/bin/llvm-readelf" \
  -h private/native-checks/triangle.o
```

Both commands returned 0. Compilation emitted no diagnostics; the object header
reports `ELF64`, little endian, `REL`, `AArch64`. This checks the renderer's C++
against the real Android headers. It does not link SDL, compile the GPU shaders
or establish a working APK.

With SDL3 installed, the app source also compiles against its actual AAR headers:

```bash
"$NDK/toolchains/llvm/prebuilt/darwin-x86_64/bin/clang++" \
  --target=aarch64-linux-android23 -std=c++17 \
  -Wall -Wextra -Wpedantic -Werror -fPIC \
  -I private/native-checks/sdl-headers \
  -c native/app/main.cpp -o private/native-checks/main.o
```

The include directory contains headers extracted from the installed AAR's
`prefab/modules/SDL3-Headers/include/` directory. The command returned 0 with no
diagnostics. This checks compilation of the input/lifecycle code, not linking or
device behaviour.

## Build configuration

Gradle 8.9 configured the Android project successfully with JDK 21 and the
installed SDK, using a project-local copy of cached dependencies and
`--offline --no-daemon help`. The same check through the generated wrapper also
passed, using the already cached Gradle distribution:

```bash
export GRADLE_USER_HOME="$PWD/private/gradle"
./android/gradlew -p android --offline --no-daemon help
```

`JAVA_HOME` and `ANDROID_HOME` pointed to the installed JDK 21 and SDK. Result:

```text
BUILD SUCCESSFUL in 5s
1 actionable task: 1 executed
```

The wrapper was generated by the cached Gradle installation without downloads.
Its JAR SHA-256 is
`498495120a03b9a6ab5d155f5de3c8f0d986a449153702fb80fc80e134484f17`,
which matches Gradle's [official checksum](https://gradle.org/release-checksums/#v8.9).
The distribution ZIP checksum is pinned in the wrapper properties. Configuration
does not run the CMake compiler, resolve the missing SDL AAR or build an APK.

## APK build and inspection

The first offline build lacked `com.google.prefab:cli:2.1.0`. The subsequent
build with dependency downloads enabled completed:

```bash
./android/gradlew -p android --no-daemon :app:assembleDebug
```

Reported build output:

```text
BUILD SUCCESSFUL in 17s
36 actionable tasks: 10 executed, 26 up-to-date
```

SDK XML version/package-element warnings appeared, but did not prevent this
build. The produced APK was independently inspected with the installed tools:

```bash
"$ANDROID_HOME/build-tools/34.0.0/apksigner" verify --verbose \
  android/app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/build-tools/34.0.0/aapt" dump badging \
  android/app/build/outputs/apk/debug/app-debug.apk
shasum -a 256 android/app/build/outputs/apk/debug/app-debug.apk
```

All returned 0. Signature schemes v1 and v2 verify; apksigner also prints a
warning about the Gradle metadata entry's v1 signature coverage. The package is
`com.proevolutica.viewer`, launch activity `.ViewerActivity`, minimum API 23,
target API 35, required OpenGL ES 3.0 and native ABI `arm64-v8a` only.

APK size: 3,779,654 bytes. SHA-256:
`5fd5ec8292f90d1f4850b18562b54730fa1b6ada45ca618d1f03fee04bdaf96e`.
This identifies the inspected debug build; later builds may have different hashes.

A separate ZIP/ELF check passed every entry's CRC and found exactly three native
libraries: `libmain.so`, `libSDL3.so` and `libc++_shared.so`, all ELF64,
little-endian AArch64. There are no packaged `assets/` files. `llvm-readelf`
confirms `libmain.so` exports `SDL_main` and depends on SDL3, GLESv3 and the C++
runtime. The inspection report remains under ignored
`private/native-checks/apk-check.json`.
